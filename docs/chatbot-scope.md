# PDF 페이지 챗봇 시연 범위

백엔드 `main`의 [48c9ad8](https://github.com/NLP-Ieobom/Ieobom/commit/48c9ad8d360d1992d13ff42cfeb2f043349f74ee)에 있던 페이지 단위 질문에 최근 대화 전달과 응답 유형을 추가했다. PDF 뷰어는 `/ask`의 응답을 표시하고 근거 ID로 기존 좌표를 찾아 강조할 수 있다. [`/ask` 계약과 오류 응답](api.md#추가-질문과-상태-확인)

## 시연에서 제공할 기능

분석이 끝난 PDF의 현재 페이지를 보면서 여러 번 이어 묻는다. 질문마다 현재 페이지의 본문과 표 텍스트, 최근 대화를 보내고, 답변의 근거를 누르면 그 페이지의 원문 블록이 강조된다. 대화는 화면 세션에 두고 문서나 페이지가 바뀌면 새 대화를 시작한다.

| 작업 | 범위 | 난이도와 예상 작업량 |
| --- | --- | --- |
| 백엔드 | `/ask`는 `history`의 최근 3쌍으로 후속 질문을 이해한다. `answer_status`로 원문 근거가 있는 답변, 짧은 대화, 근거가 부족한 경우를 나눈다. `question`만 보내는 호출도 지원한다. | 구현 완료 |
| 프론트엔드 | 입력·답변·재시도 UI, 페이지를 바꾼 뒤 도착한 응답 무시, 기존 `/learning.evidence_blocks`를 이용한 원문 강조. 제외·분석 중인 페이지에서는 질문 버튼을 비활성화한다. | 중간, 0.5~1인일 |
| 통합 검증 | 시연 PDF에서 첫 질문과 대명사를 쓰는 후속 질문, 근거 클릭, 근거 부족, 페이지 이동을 확인한다. 타인 문서 요청과 Gemini 오류의 응답도 확인한다. | 0.5인일 |

PDF 뷰어와 로그인 연동이 준비되어 있고 서버에서 Gemini 호출이 가능하면 남은 화면 연결과 통합 검증은 **1~1.5인일**로 잡는다. 팀 뷰어가 PDF 페이지 이동과 블록 강조를 제공하는지 확인한 뒤 연결한다.

문서 전체 검색, 영구 대화 저장, 토큰 스트리밍, 수식·이미지 입력은 별도 작업으로 잡는다. 문서 전체 검색과 영구 저장까지 추가하면 검색 결과 검증과 데이터 수명 관리를 포함해 **추가 3~5인일 이상**으로 추정한다. 현재 페이지 챗은 기존 추출·좌표 데이터를 재사용한다.

## 완료 판정

1. 분석 완료 PDF 5쪽에서 질문을 보내고, 곧이어 “그게 왜 필요한 거야?”라고 물으면 바로 앞 질문을 이어서 설명한다.
2. 답변의 근거를 클릭하면 같은 페이지의 실제 블록에 박스가 표시된다. 근거가 부족한 질문에는 부족하다고 표시한다.
3. 다른 페이지로 넘어가면 새 대화를 시작하고, 이전 페이지 답변으로 현재 화면을 바꾸지 않는다.
4. 타인 문서는 404로 처리하고, Gemini 호출이 실패하면 사용자에게 재시도를 제공한다.
