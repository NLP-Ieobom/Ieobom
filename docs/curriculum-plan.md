# 커리큘럼 선택과 수강 지도 계획

2026년 11월 19일 기준 구현 보류. 프론트 화면 작업을 시작할 때 아래 흐름과 응답 형태를
맞춘 뒤 백엔드를 구현한다. 지금은 계획만 남긴다.

기존 설계는 [아키텍처의 데이터 모델](architecture.md#데이터-모델)을 따른다.
현재 구현된 것은 `course`, `user_course`, 전체 과목 조회와 내 과목 조회다.
커리큘럼 선택, 수강 등록 API, 과목 관계와 지도 조회는 아직 없다.

## 사용자 흐름

1. 학교·학과·적용 연도로 구분한 커리큘럼 목록을 본다.
2. 하나를 내 커리큘럼으로 선택한다.
3. 선택한 커리큘럼에 속한 과목 목록을 본다.
4. 듣는 과목을 수강 등록한다.
5. 커리큘럼 지도에서 과목 사이의 관계를 보고, 등록한 과목은 색으로 구분한다.
   과목을 누르면 기존 과목별 PDF 목록으로 들어간다.

커리큘럼은 선택하고, 과목은 수강 등록한다고 부른다.
학교의 실제 수강신청과 연동하는 기능은 아니다.

## 데이터와 API 초안

사용자가 커리큘럼 하나를 선택하고, 과목 행도 커리큘럼 하나에 속하는 안으로 시작한다.
이 기준이면 `curriculum`을 만들고 `user.curriculum_id`, `course.curriculum_id`로 연결할 수 있다.
여러 커리큘럼에서 같은 과목 행을 공유해야 한다면 소속 관계를 별도 테이블로 빼야 한다.
이 부분은 구현 전에 정한다.

수강 등록은 기존 `user_course`를 쓴다. 처음에는 등록 여부만 표시하고, 수강 완료 상태는
필요한 화면이 정해지면 추가한다. 색상은 프론트에서 정하고 백엔드는 등록 여부를 내려준다.
수강 등록을 취소해도 업로드한 PDF와 메모는 지우지 않는다.

아래 경로는 협의용 초안이다. 공통 접두사는 `/api/v1`이다.

| 기능 | API 후보 |
| --- | --- |
| 커리큘럼 목록 | `GET /curricula` |
| 내 커리큘럼 조회·선택 | `GET /curricula/me`, `PUT /curricula/me` |
| 커리큘럼별 과목 목록 | `GET /courses?curriculum_id=...` |
| 과목 수강 등록·취소 | `PUT /courses/{id}/enrollment`, `DELETE /courses/{id}/enrollment` |
| 커리큘럼 전체 지도 | `GET /curricula/{id}/map` |

지도 응답은 과목 목록과 과목 간 연결 목록으로 나눈다. 과목마다 내 등록 여부를 포함한다.
기존 명세의 `/courses/{id}/map`은 과목 중심 지도이므로, 전체 지도와 둘 다 필요한지는
화면에서 정한다. `/courses`의 필터 없는 요청과 `/courses/me`의 조회 범위도 그때 맞춘다.

## 사용할 교육과정 자료

`origin/pdf_extraction` 브랜치의 `docs/extraction/demo/ieobom-ssu-corpus.zip`에
숭실대 AI소프트웨어학부 2026학년도 입학생 기준 교육과정 52과목과 대표 강의계획서
49과목이 있다. 현재 확보한 커리큘럼은 하나다. 여러 개를 보여 주려면 다른 적용 연도나
학과의 실제 자료가 더 필요하다.

이 자료는 과목 코드 `21501654`와 분반별 개설 코드 `2150165402`를 구분한다.
지도는 과목 단위로 구성하는 안을 쓴다. 운영 DB의 운영체제 코드는 현재 `2150165402`이므로
자료를 넣기 전에 코드 대응을 정리한다. 기존 과목 UUID를 유지해 PDF와 수강 등록 연결을 보존한다.
학기·분반 선택까지 지원할지는 아직 정하지 않았다.

현재 자료에는 선수과목과 추천 연결이 채워져 있지 않다. 학년·학기 배치만으로 선수 관계를
만들지 않는다. 관계 자료를 확보하기 전에는 연결선 없이 과목 배치와 수강 표시부터 가능하다.

## 재개할 때 작업 순서

1. 프론트와 선택·등록·지도 화면을 맞추고 미정 사항을 정한다.
2. 커리큘럼과 과목 소속을 마이그레이션하고, 확보한 교육과정 한 개를 등록한다.
   과목 코드 대응과 기존 문서 연결을 확인한다.
3. 내 커리큘럼 선택과 커리큘럼별 과목 조회를 구현한다.
4. 기존 `user_course`에 수강 등록·취소 API를 붙인다.
5. 과목 관계 자료를 정리하고 지도 응답에 내 수강 여부를 합친다.
6. 커리큘럼 선택부터 과목 등록, 지도 표시, 기존 PDF 열람까지 연결해서 확인한다.
   다른 사용자의 등록 상태와 문서가 섞이지 않는지도 확인한다.

화면을 맞출 때는 커리큘럼을 하나만 선택하는지, 선택을 바꾼 뒤 이전 수강 기록을 어떻게
보여 줄지, 수강 중과 완료를 구분할지부터 정한다. 분반 선택과 같은 과목의 커리큘럼 간
공유 여부는 과목 식별 방식에 영향을 주므로 데이터 등록 전에 정해야 한다.

작업은 위 기능 단위로 나눈다. 운영 반영 전에는 기존 PDF·메모·수강 연결을 확인한다.
