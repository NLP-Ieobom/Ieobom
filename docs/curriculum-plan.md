# 커리큘럼 선택과 수강 지도 계획

커리큘럼 목록·지도, 과목 수강 상태 변경, PDF 열람 진도를 구현했다. 운영 반영 전에는
마이그레이션과 데모 자료 등록 스크립트를 실행해야 한다. 내 커리큘럼 선택을 계정에 저장하는
기능은 아직 없다. 지도 화면에서는 조회할 커리큘럼 ID를 직접 넘긴다.

기존 설계는 [아키텍처의 데이터 모델](architecture.md#데이터-모델)을 따른다.
커리큘럼 안에 과목이 있고, 과목 안에서 본인이 올린 PDF를 골라 공부한다.
커리큘럼과 과목은 공용 목록이고 문서와 메모는 사용자별 데이터다.

## 사용자 흐름

1. 학교·학과·적용 연도로 구분한 커리큘럼 목록을 본다.
2. 조회할 커리큘럼 하나를 누른다.
3. 선택한 커리큘럼에 속한 과목 목록을 본다.
4. 과목을 수강 중이나 완료 상태로 표시한다.
5. 커리큘럼 지도에서 과목 사이의 관계를 보고, 수강 상태에 따라 색을 구분한다.
   과목을 누르면 기존 과목별 PDF 목록으로 들어간다.

커리큘럼은 선택하고, 과목은 수강 등록한다고 부른다.
학교의 실제 수강신청과 연동하는 기능은 아니다.

## 현재 테이블과 조회 API

과목 행은 커리큘럼 하나에 속하도록 시작한다. 기존 과목 중 소속을 아직 확인하지 않은 것은
`curriculum_id = NULL`로 유지한다. 여러 커리큘럼에서 같은 과목 행을 공유하는 기능은 없다.

| 테이블 | 변경 |
| --- | --- |
| `curriculum` | 신설. `id`, `institution`, `department`, `entry_year`, `is_demo`, `created_at` |
| `course` | `curriculum_id` 외래키·인덱스와 `(curriculum_id, course_code)` 유니크 제약 추가 |
| `course_relation` | 신설. 출발·도착 과목 ID, `relation_type`, `source` 저장 |
| `document` | 기존 연결 유지. Docling이 확인한 전체 페이지 수 `page_count` 추가 |
| `user_course` | `status` 추가. `in_progress`, `completed` 중 하나 |
| `user_document_progress` | 신설. 사용자·문서별 마지막 페이지 번호와 마지막 저장 시각 |
| `user_page_view` | 신설. 사용자·문서·페이지 번호를 복합 기본키로 사용해 중복 열람 제외 |
| `user` | 변경 없음. 내 커리큘럼 선택을 구현할 때 별도로 연결 |

`entry_year`는 입학 기준 교육과정 연도다. 같은 학교·학과·입학 연도의 커리큘럼은 중복 등록하지
않는다. 기존 과목 응답의 `curriculum_year`는 호환을 위해 남겨 두고 자료 등록 시 입학 연도로 채운다.

공통 접두사는 `/api/v1`이고, 아래 조회에는 로그인이 필요하다.

| API | 기존 동작 | 이번 변경 |
| --- | --- | --- |
| `GET /curricula` | 없음 | 커리큘럼 목록 조회 추가 |
| `GET /courses` | 전체 과목 | 유지 |
| `GET /courses?curriculum_id={id}` | 필터 미지원 | 기존 `/courses`에 커리큘럼 필터 추가 |
| `GET /courses/me` | 내 수강 과목 | 수강 상태·열람 진도와 선택 필터 `curriculum_id` 추가 |
| `GET /curricula/{id}/map` | 없음 | 전체 과목, 내 수강 상태·열람 진도, 과목 간 관계 조회 |
| `PUT /courses/{id}/enrollment` | 없음 | 수강 중·완료 상태 지정 |
| `DELETE /courses/{id}/enrollment` | 없음 | 수강 등록 취소 |
| `GET /documents?course_id={id}` | 해당 과목에 내가 올린 PDF | PDF별 열람 진도와 마지막 위치 추가 |
| `GET /documents/{id}/progress` | 없음 | PDF 열람 진도와 마지막 위치 조회 |
| `PUT /documents/{id}/progress` | 없음 | 현재 화면에 표시된 페이지 기록 |

커리큘럼 목록은 `curricula` 배열로 반환하며 각 항목에는 `id`, `institution`, `department`,
`entry_year`, `is_demo`가 들어 있다. 실제 자료를 데모보다 먼저 보여 준다.
`/courses?curriculum_id={id}`는 별도 경로가 아니라 기존 `/courses`의 선택 쿼리 파라미터다.
응답의 `courses` 배열과 기존 필드는 유지하고 각 과목에 `curriculum_id`를 추가했다.
필터 없는 `/courses`는 소속 미정 과목까지 모두 반환한다. `/courses/me`는 `user_course`에 등록된
내 과목을 수강 중·완료 모두 포함해서 반환한다. `curriculum_id`를 주면 그 커리큘럼으로 한정한다.
존재하지 않는 커리큘럼 ID로 필터하면 404,
UUID 형식이 잘못되면 422, 등록된 과목이 없는 커리큘럼이면 빈 배열이다.

커리큘럼 조회가 개인의 선택이나 수강 기록을 바꾸지는 않는다. 문서 목록에는 로그인한 사용자가
업로드한 PDF만 나온다. 문서에 `curriculum_id`를 중복 저장하지 않고 과목을 통해 소속을 찾는다.

## 수강 상태와 지도

수강 상태는 PDF 열람 진도와 별개로 사용자가 직접 지정한다. PUT 요청 본문은
`{"status": "in_progress"}` 또는 `{"status": "completed"}`다. 처음부터 완료로 등록하거나,
완료한 과목을 다시 수강 중으로 돌릴 수 있다. 같은 요청을 반복해도 등록 행은 하나만 유지한다.
기존 `user_course` 행은 마이그레이션에서 `in_progress`로 채운다.

DELETE는 등록 행만 지우고 204를 반환한다. PDF, 질문, 메모, 열람 기록은 유지한다.
이 상태에서 지도 응답의 `enrollment_status`는 `not_enrolled`가 된다. 학기별 수강 이력은 저장하지 않는다.

지도 응답에는 `curriculum`, `courses`, `relations`가 있다. `courses`는 선택한 커리큘럼의
전체 과목이며 각 항목에 `enrollment_status`와 `reading_progress`를 포함한다. 프론트는
미등록 과목을 흑백으로, 수강 중과 완료 과목을 각각 다른 색이나 완료 표시로 구분할 수 있다.
색상과 배치 좌표는 프론트에서 정한다. 현재 데이터에는 학년·학기별 배치 정보가 없다.

`relations`의 항목에는 `id`, `source_course_id`, `target_course_id`, `relation_type`, `source`가
들어 있다. 출발·도착 과목이 모두 해당 커리큘럼에 속한 관계만 반환한다. 등록한 관계가 없으면
빈 배열이며, 과목 목록에서 관계를 자동으로 추측하지 않는다. 관계 유형과 출처를 화면에서도 구분한다.

## PDF 열람 진도와 이어보기

진도는 실제 화면에 표시되어 기록된 서로 다른 페이지 수를 전체 페이지 수로 나눈 값이다.
같은 페이지를 반복해서 열어도 한 번만 센다. 24쪽 PDF에서 1쪽과 24쪽만 열면 2/24인 8.33%다.
다시 1쪽을 열면 비율은 그대로이고 마지막 페이지 번호만 1로 바뀐다. 열람 여부를 나타내는 값이며
내용을 이해했거나 학습을 완료했다는 뜻은 아니다.

과목 진도는 본인이 업로드 완료한 PDF들의 열람 페이지 수와 전체 페이지 수를 각각 합산해서
계산한다. 다른 사용자의 PDF와 업로드 미완료 문서는 제외한다. 새 PDF를 추가하면 분모가 늘어나
진도가 내려갈 수 있다. PDF 진도가 100%여도 과목 상태를 자동으로 완료로 바꾸지 않는다.

페이지 수는 Docling 추출이 끝날 때 `document.page_count`에 저장한다. `document_page`는 메모 등으로
일부 페이지만 만들어질 수 있으므로 그 행 수를 전체 페이지 수로 쓰지 않는다. 페이지 수를 아직 모르면
`total_pages`, `progress_percent`를 null로 반환한다. 과목에 그런 PDF가 하나라도 있으면 과목 전체
비율도 null이다. 과목에 업로드 완료한 PDF가 없으면 페이지 수는 0, 비율은 null이다.

페이지 기록 요청은 다음과 같다.

```http
PUT /api/v1/documents/{id}/progress
Content-Type: application/json

{"page_number": 7}
```

응답에는 `document_id`, `viewed_pages`, `total_pages`, `progress_percent`, `last_page_number`,
`last_viewed_at`가 들어 있다. GET도 같은 형식이다. 문서 목록의 `reading_progress`에는 문서 ID를
제외한 같은 필드가 있고, 지도와 내 과목 목록에는 페이지 수와 비율만 있다.

페이지 번호는 1부터 전체 페이지 수까지만 받는다. 업로드 미완료이거나 페이지 수가 아직 없으면
409, 페이지 범위를 벗어나면 422다. 다른 사용자 문서는 조회·저장 모두 404다. 저장 요청 한 번에
열람 페이지 기록과 마지막 위치를 같은 트랜잭션으로 갱신한다. 수강 등록을 하지 않은 과목의 PDF도
본인 문서라면 열람 기록을 남길 수 있다.

프론트 연동 순서는 다음과 같다.

1. 문서 목록의 `reading_progress`나 별도 GET으로 마지막 페이지를 확인한다. 기록이 없으면 1쪽을 연다.
2. 페이지가 실제로 화면에 표시될 때 PUT을 보낸다. 질문·메모 GET은 기존처럼 별도로 호출한다.
3. 빠른 페이지 이동에서도 저장 순서가 뒤집히지 않도록 같은 PDF의 PUT은 순서대로 전송한다.
   미리 불러온 페이지나 질문 패널의 자동 재조회는 열람으로 기록하지 않는다.
4. 페이지 수 미확정으로 409를 받으면 추출 상태를 확인하고 페이지 수가 준비된 후 현재 페이지를 기록한다.

마지막 위치는 서버에 마지막으로 저장된 페이지다. 브라우저 종료 자체를 감지하는 값은 아니며,
마지막 PUT이 전송되기 전에 연결이 끊기면 직전 기록에서 이어진다. 페이지 안의 스크롤 위치는 저장하지 않는다.

기존 분석 잡에 전체 페이지 수가 있으면 마이그레이션에서 문서로 옮긴다. 기존 잡에도 없는 문서는
추출 결과를 확인해 `page_count`를 채워야 열람 기록을 시작할 수 있다. 예전 질문·메모 조회를 근거로
과거 열람 기록을 만들어 넣지는 않는다.

## 사용할 교육과정 자료

숭실대 AI소프트웨어학부 데이터는 팀원이 정리해서 추가할 예정이므로 이번 등록에서 제외한다.
저장소의 `docs/extraction/demo/ieobom-ssu-corpus.zip`은 그대로 두고 등록 스크립트에서 읽지 않는다.
실제 과목의 코드 정리와 커리큘럼 연결은 자료를 받은 뒤 진행한다.

다른 커리큘럼 선택 시연에는 `데모대학교 / 경영학부 / 2026`을 쓴다. 경영학원론, 회계원리,
마케팅원론, 재무관리, 조직행동론 5과목을 임의로 구성했다. 실제 경영학부 교육과정 자료가 아니며
`is_demo = true`와 `DEMO-BUS-` 과목 코드로 구분한다.

기존 운영체제 과목의 UUID와 코드 `2150165402`는 변경하지 않는다. 소속을 아직 등록하지 않았으므로
`curriculum_id`는 NULL로 남는다. 전체 과목과 내 수강 과목 조회, 기존 PDF 연결은 그대로 사용할 수 있다.
학기·분반 선택까지 지원할지는 아직 정하지 않았다.

경영학부 데모에는 화면 시연용 연결 3개를 등록한다. 경영학원론에서 마케팅원론·조직행동론으로,
회계원리에서 재무관리로 이어지는 임의 관계다. `relation_type = recommended`, `source = demo`로
구분하며 실제 선수과목 관계로 표시하지 않는다. 실제 과목 관계는 팀원 자료를 받은 뒤 확인한다.

## 자료 등록

`DATABASE_URL`을 지정한 환경에서 저장소 루트를 기준으로 실행한다.

```sh
cd backend
alembic upgrade head
python -m app.scripts.seed_curricula
```

스키마 마이그레이션만으로 과목 데이터가 들어가지는 않는다. 등록 스크립트는 경영학부 데모
커리큘럼 하나와 5과목, 데모 연결 3개를 한 트랜잭션에서 등록한다. 다시 실행해도 같은 UUID를 사용한다.
기존 실제 과목의 코드·소속과 문서·수강 기록은 변경하지 않는다.

## 남은 작업 순서

1. 프론트에 지도, 수강 상태 변경, 페이지 표시 시 기록, 이어보기를 연결한다.
2. 팀원이 정리한 실제 과목·관계 자료를 등록한다. 학년·학기별 배치에 필요한 정보도 함께 확인한다.
3. 계정에 내 커리큘럼 선택을 저장할 필요가 생기면 `user.curriculum_id` 추가를 검토한다.

학기별 수강 이력, 분반 선택, 여러 커리큘럼에서 같은 과목 공유는 아직 범위에 없다.
